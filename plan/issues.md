# recs issue audit

This is a source and test audit, not a runtime or hardware validation. I inspected the package, CLI entry points, test inventory, and the relevant sibling `reccy` implementations on 2026-09-29. I did not execute the application or tests because this change is documentation-only. Locations below refer to the current tree. "Confirmed" means the behavior follows directly from the cited code; "risk" means the failure needs a particular scheduling, I/O, or external-device condition. Priorities reflect potential data loss and whether a normal user can encounter the condition. Existing tests often cover the happy path; a suggested test is a missing *failure-mode* test, not a claim that the whole module is untested.

## P0: data integrity and recording safety

1. **Names can turn into path components or escape the recording root (confirmed).** `PathPattern.make_path` formats device/track aliases into a string before calling `Path` and `legal_path`; `make_track_name_path` does the same with user-defined track names ([recs/cfg/path_pattern.py:95](../recs/cfg/path_pattern.py#L95), [recs/cfg/path_pattern.py:114](../recs/cfg/path_pattern.py#L114)). `reccy.paths.legal_path` sanitizes *existing path components*, not `/` separators or `..`; `validate_track_names` only rejects empty names ([recs/cfg/track_names.py:6](../recs/cfg/track_names.py#L6)). Thus `AC/DC` changes the directory layout, and a name containing parent components can resolve outside the intended output directory. Sanitize each substituted filename fragment before path construction, reject `.`/`..` components, and verify the resolved result stays under the selected recording root. Test aliases and track names containing `/`, `..`, and platform-specific forbidden characters.

2. **Output files are not claimed atomically (risk of overwriting another recorder's audio).** `FileOpener.open` checks `path.exists()` then opens libsndfile in `mode='w'` ([recs/audio/file_opener.py:18](../recs/audio/file_opener.py#L18)); the loop in `create` only retries if that prior check saw a file. Another process can create the same path between check and open, and the existing file can be truncated. Session directory selection has the same check-then-return pattern ([recs/recording/recording_paths.py:157](../recs/recording/recording_paths.py#L157)). Use an exclusive/reserved output path or an equivalent atomic claim before libsndfile writes; exercise simultaneous recorders in a targeted concurrency test.

3. **Source-update coalescing silently drops durable file history (confirmed).** `_merge_files` and `_merge_file_map` retain only the most recent 512 paths ([recs/runtime/source_transport.py:165](../recs/runtime/source_transport.py#L165), [recs/runtime/source_transport.py:256](../recs/runtime/source_transport.py#L256), [recs/runtime/source_transport.py:291](../recs/runtime/source_transport.py#L291)). This applies to files, starts, finishes, discards, end frames, timestamps, and spans when the parent is behind. `Recorder._record_device_file_update` uses those updates to build the session record ([recs/runtime/recorder.py:230](../recs/runtime/recorder.py#L230)). The existing merge test explicitly asserts this bound ([test/runtime/test_source_recorder.py:347](../test/runtime/test_source_recorder.py#L347)), but does not establish that omitted file events are recoverable. Treat durable file events separately from lossy telemetry, and test a backlog exceeding 512 against a complete final session document.

4. **A failed file-format open leaks earlier outputs and leaves them unjournaled (confirmed).** `ChannelWriter._open` opens every requested format in a list comprehension, then registers the paths only after all opens succeed ([recs/audio/channel_writer.py:198](../recs/audio/channel_writer.py#L198)). If a later format fails (disk full, unsupported codec, permissions), earlier `SoundFile`s are not closed or entered in `files_written`. `FileOpener.open` also does not close an opened file if metadata assignment fails ([recs/audio/file_opener.py:36](../recs/audio/file_opener.py#L36)). Close partial outputs on failure and decide explicitly whether to discard or journal them. Test failure on the second format.

5. **Journal write failure can prevent orderly shutdown (confirmed failure path).** `SessionRecordWriter.write` lets write/flush `OSError` escape, whereas only `fsync` errors are accumulated ([recs/recording/session_record.py:252](../recs/recording/session_record.py#L252)). `Recorder.run` calls `_finish_record` in `finally` after other cleanup ([recs/runtime/recorder.py:356](../recs/runtime/recorder.py#L356)); `RecordingSession.finish` writes several final entries before closing the writer ([recs/recording/recording_session.py:55](../recs/recording/recording_session.py#L55)). A full or disconnected output disk can therefore abort finalization and leave the record handle open, masking the original failure. Ensure close/cleanup occurs even when final journal writes fail, retain a visible error, and inject a failed write/flush during shutdown in a test.

6. **Project switch is not transactional (confirmed failure path).** `_switch_project` mutates the active configuration, device controls, identity, settings path, and possibly session before `_publish_instance` and `_new_session` finish. On `OSError`, `RecsError`, or `ValueError`, it releases only the new settings claim; it does not restore any earlier state ([recs/runtime/recorder.py:813](../recs/runtime/recorder.py#L813)). A failed new-session open can leave the recorder configured for the new project while the old session/claim is still live, and writing may remain suspended ([recs/runtime/recorder.py:513](../recs/runtime/recorder.py#L513)). Prepare all fallible resources first or add a narrow rollback for this operation. Test failure at each publication/session boundary.

   A related collision path should be checked in the same work: `SessionRecordWriter` silently chooses `session-record-1.jsonl` when the requested journal exists ([recs/recording/session_record.py:233](../recs/recording/session_record.py#L233), [recs/recording/session_record.py:366](../recs/recording/session_record.py#L366)), while unfinished-session registration and clearing use the originally requested `session-record.jsonl` ([recs/runtime/recorder.py:752](../recs/runtime/recorder.py#L752), [recs/runtime/recorder.py:782](../recs/runtime/recorder.py#L782)). A journal collision could therefore leave recovery tracking attached to the wrong file. Reserve the directory/journal once, and pass the actual journal path through all lifecycle calls.

## P1: shutdown, concurrency, and resource exhaustion

7. **A timed-out control may still execute later (confirmed).** External RPC puts a request in both `_requests` and `_pending`; on timeout it removes only `_pending` ([recs/daemon/external_ipc.py:91](../recs/daemon/external_ipc.py#L91), [recs/daemon/external_ipc.py:152](../recs/daemon/external_ipc.py#L152)). Once the recorder loop catches up, it can run a mutation after the client was told it failed. The GUI path likewise retains a timed-out queued request ([recs/daemon/gui_ipc.py:36](../recs/daemon/gui_ipc.py#L36), [recs/daemon/gui_ipc.py:439](../recs/daemon/gui_ipc.py#L439)). Define cancellation/commit semantics and return an honest timeout if an operation has already begun. Test a deliberately stalled recorder loop.

8. **GUI shutdown sends fabricated success responses (confirmed).** `DaemonGuiServer.request_shutdown` answers every pending request with `RecordingState(paused=False)`, irrespective of request type or whether it ran ([recs/daemon/gui_ipc.py:259](../recs/daemon/gui_ipc.py#L259)). A client can report a successful pause/switch/new-session response for an action that never occurred. Reply with a protocol error, as the external RPC shutdown path does ([recs/daemon/external_ipc.py:171](../recs/daemon/external_ipc.py#L171)).

9. **Several shutdown waits are unbounded (risk).** `SourceUpdateTransport.finish` waits forever for `idle` if its pipe send remains blocked ([recs/runtime/source_transport.py:114](../recs/runtime/source_transport.py#L114)). After the initial timeout, `SourceProcess.join` calls `process.join()` without a timeout, then joins the drain thread without one ([recs/runtime/source_process.py:242](../recs/runtime/source_process.py#L242)). Playback stop also joins its PortAudio-writing thread without a timeout ([recs/audio/playback.py:104](../recs/audio/playback.py#L104)). A stuck device, pipe, or filesystem operation can turn Ctrl-C/service stop into an indefinite wait. Give shutdown an overall deadline, surface incomplete termination, and test permanently stalled workers as well as merely slow ones.

10. **Source control coalesces one-shot commands as if they were state (risk).** `SourceControlTransport.publish` keeps only the latest `calibration_tracks` and configuration revision while the sending thread is blocked ([recs/runtime/source_process.py:41](../recs/runtime/source_process.py#L41)); `SourceProcess.calibrate` submits calibration through that channel ([recs/runtime/source_process.py:222](../recs/runtime/source_process.py#L222)). Coalescing a desired setting is reasonable, but dropping a calibration request or an acknowledgement-bearing revision can strand a waiting caller or make audit events incomplete. Separate commands from replaceable state and test two requests while the control pipe is blocked.

   The reverse channel also replaces a queued `SourceUpdate` outright when a `SourceFailure` arrives ([recs/runtime/source_transport.py:95](../recs/runtime/source_transport.py#L95)). If the update contains final file metadata and the failure is published before the sender takes it, the parent sees the failure but loses the queued update. Preserve durable update data ahead of terminal failure and test that ordering.

11. **Device-query stream has a restart/reader race (risk).** `_read` dereferences mutable `self.process.stdout`; `stop` closes it, sets `self.process` and `self.reader` to `None`, and does not join the reader before restart ([recs/runtime/device_poller.py:88](../recs/runtime/device_poller.py#L88), [recs/runtime/device_poller.py:136](../recs/runtime/device_poller.py#L136)). A reader can observe `None`, a closed stream, or a newer process's stream. Capture the stream locally for each reader and join/identify that reader on restart. Add repeated fast restart tests.

12. **A valid but malformed device-query JSON value can kill polling (confirmed).** `_read` catches only JSON syntax errors and queues any JSON value; `DevicePoller.poll` assumes an iterable of dicts containing `name` and `max_input_channels` ([recs/runtime/device_poller.py:41](../recs/runtime/device_poller.py#L41), [recs/runtime/device_poller.py:136](../recs/runtime/device_poller.py#L136)). A helper regression or truncated schema can raise `TypeError`/`KeyError` in the polling thread. Validate the message shape at the boundary and report/restart cleanly. Also handle `Popen` failure at start ([recs/runtime/device_poller.py:68](../recs/runtime/device_poller.py#L68)) so process-limit exhaustion is a user-visible warning rather than an abrupt startup exception.

13. **MIDI and card-replacement buffers can grow without bound (confirmed).** `CallbackPort.capture` feeds an unbounded `SimpleQueue` while the recorder drains it only during polling ([recs/midi/recorder.py:343](../recs/midi/recorder.py#L343)). MIDI and OSC also append to unbounded card-replacement lists for as long as media is unavailable ([recs/midi/recorder.py:65](../recs/midi/recorder.py#L65), [recs/osc/recorder.py:319](../recs/osc/recorder.py#L319)). A high-rate device or long card outage can exhaust memory. Define bounded retention, dropped-event accounting, and a visible warning; test sustained input and extended replacement.

14. **Continuous OSC input can monopolize the recorder loop (risk).** `OscNodeRecorder.poll` receives until `BlockingIOError` with no packet or time budget ([recs/osc/recorder.py:166](../recs/osc/recorder.py#L166)). If packets arrive faster than they are decoded/written, the call need not return, delaying audio/device checks, controls, and shutdown. Limit packets or elapsed time per poll and record lag/drop statistics.

15. **A transient DNS failure permanently disables outbound OSC for that run (confirmed).** Hostname resolution starts once; on `getaddrinfo` failure it queues an error, but `_receive_resolved_target` only records the failure and no later poll starts another resolution ([recs/osc/recorder.py:137](../recs/osc/recorder.py#L137), [recs/osc/recorder.py:259](../recs/osc/recorder.py#L259)). Poll/subscription/command traffic never resumes after DNS recovers. Retry resolution with bounded backoff and test failure followed by recovery. UDP packet loss itself is not detected; document that OSC delivery is best effort rather than implying acknowledgement.

16. **Warnings/status can grow for the entire recording (risk).** `Recorder.warnings` retains every distinct warning string, and `RecordingSession.record_errors` retains every finalization/sync error ([recs/runtime/recorder.py:91](../recs/runtime/recorder.py#L91), [recs/runtime/recorder.py:965](../recs/runtime/recorder.py#L965), [recs/recording/recording_session.py:30](../recs/recording/recording_session.py#L30)). Source warnings are bounded in transport, but varying per-error text can still grow parent state over a long unattended run. Cap display history while keeping durable diagnostics, and test high-cardinality repeated failures.

17. **`recs watch` buffers events without a bound before its initial snapshot (risk).** `StatusWatcher.receive` appends every event to `pending` until `set_snapshot` runs ([recs/daemon/watch.py:45](../recs/daemon/watch.py#L45), [recs/daemon/watch.py:63](../recs/daemon/watch.py#L63)). A slow/hung control RPC plus active waveform or status publication can consume unbounded memory. Bound the pre-snapshot queue or coalesce replaceable status events.

18. **GUI accept holds a shared lock while writing to an unwanted client (risk).** `_accept` sends the "already active" error while holding `self.lock` ([recs/daemon/gui_ipc.py:277](../recs/daemon/gui_ipc.py#L277)). A slow local pipe/client can block status publication and shutdown paths needing the same lock. Decide under lock, then perform I/O outside it. Also reject controls appended after `shutdown_started` ([recs/daemon/gui_ipc.py:309](../recs/daemon/gui_ipc.py#L309)).

## P2: errors, APIs, maintenance, and performance

19. **Invalid file input uses an assertion instead of a user error (confirmed).** `FileSource.__init__` asserts the path exists, then opens it with libsndfile ([recs/cfg/file_source.py:17](../recs/cfg/file_source.py#L17)). Missing paths yield `AssertionError` (or a less clear libsndfile error with optimized Python) rather than `RecsError` naming the input. Validate with an ordinary exception and test missing, unreadable, and malformed audio inputs.

20. **Recovery/export use a duplicate, collision-prone atomic writer (confirmed).** `recording_paths.write_text_atomically` always uses `.{name}.tmp` ([recs/recording/recording_paths.py:206](../recs/recording/recording_paths.py#L206)); two writers to the same report/progress path can interfere. `reccy.configuration.settings.write_text_atomically` already uses `reccy.runtime.files.atomic_output`, which creates a unique sibling temporary file. Reuse that service for recovery reports, worklists, and export progress ([recs/recording/recovery_report.py:165](../recs/recording/recovery_report.py#L165), [recs/recording/session_export.py:131](../recs/recording/session_export.py#L131)); test concurrent publication.

21. **Export publication has a destination race (risk).** `session_export.export` checks that the destination does not exist, spends time copying/verifying, checks again, then calls `temporary.rename(destination)` ([recs/recording/session_export.py:35](../recs/recording/session_export.py#L35), [recs/recording/session_export.py:212](../recs/recording/session_export.py#L212)). Another process can create a destination after the final check; platform rename behavior can replace it, especially an empty directory. Use an atomic no-replace publication primitive or a claimed destination, and test concurrent exports. The existing staged-resume handling is otherwise a useful recovery pattern.

22. **Export path-conflict check is quadratic in asset count (confirmed).** `any(p in paths for q in paths for p in q.parents)` walks ancestors for every path ([recs/recording/session_export.py:64](../recs/recording/session_export.py#L64)); with a large session, validation can become disproportionately slow before copying begins. Compare against a set of actual relative paths with a linear or sorted-prefix walk. Benchmark with many assets before changing it.

23. **Project identity and persistence semantics are easy to misread (confirmed).** `projects.load(name)` accepts a JSON `name` that differs from its filename and `configured` uses the requested filename as the active project ([recs/cfg/projects.py:81](../recs/cfg/projects.py#L81), [recs/cfg/projects.py:91](../recs/cfg/projects.py#L91)). `project save` stores config and track layout but not the musicians held in mutable settings ([recs/cfg/projects.py:113](../recs/cfg/projects.py#L113)), while `project use` starts a recorder and `project switch` changes a running one ([recs/cfg/projects.py:132](../recs/cfg/projects.py#L132)). Consider validating file/internal identity and clarifying in help which data is a reusable project definition versus mutable workspace; keep any semantic change explicit.

24. **Project delete and list leak raw filesystem errors (confirmed).** `project save`/`load` turn `OSError` into contextual `RecsError`, but `delete` calls `unlink` directly and `list` iterates the directory directly ([recs/cfg/projects.py:147](../recs/cfg/projects.py#L147)). Permission or filesystem failures produce a traceback instead of a project-specific message. Apply the same error policy; test an inaccessible config directory.

25. **OSC node filename validation is incomplete across platforms (confirmed).** `Node.validate_name` rejects only slashes ([recs/osc/config.py:67](../recs/osc/config.py#L67)); `_next_path` uses the name directly as a filename ([recs/osc/recorder.py:358](../recs/osc/recorder.py#L358)). Names containing `:`, `*`, `?`, etc. are invalid on Windows, and special names can be ambiguous. Use `reccy.paths.legal_filename` consistently or reject invalid names before startup, with a Windows-oriented test.

26. **`play` failure can leave recording paused (risk).** `PlaybackControl.play` pauses capture before constructing/starting the playback worker and has no cleanup if `PlaybackRunner.start` fails ([recs/runtime/playback_control.py:64](../recs/runtime/playback_control.py#L64)). Thread/process resource exhaustion can leave `resume_after_playback` set and the recording paused with no running playback. Make start failure restore capture and close the timeline. Separately, `PlaybackRunner.stop` needs the shutdown deadline noted above.

27. **A few names hide different operations (API trap).** The playback API uses negative `session` values (`len(paths) + request.session`) while the field itself is not named `relative_session` ([recs/runtime/playback_control.py:45](../recs/runtime/playback_control.py#L45)); `stop` means stop playback in that component but stop the recorder elsewhere; `project use` versus `project switch` also encode start-versus-live semantics only in help. Prefer explicit names/help and errors over silently accepting misleading indices. This is a documentation/API review item, not a call for a broad rename.

28. **Large orchestration files concentrate unrelated failure modes.** `recs/runtime/recorder.py` (~1,060 lines) combines session lifecycle, device polling, IPC, card replacement, disk policy, playback, warnings, and project switching; `recs/edit/commands.py` (~721) handles command discovery, parsing, and arrangement generation; `recs/recording/baccy_import.py` (~697) handles import mapping and persistence. These are review and change-risk hotspots, particularly the recorder's interleaved cleanup paths. Extract only a cohesive responsibility when fixing a concrete issue; a size-only split would add navigation without removing coupling.

29. **Tiny files are not automatically a problem.** `recs/audio/header_size.py` is ~16 lines and called from one production module, so it could be inlined when next touched. `recs/daemon/gui_backend.py` is similarly small but provides an OS-specific IPC boundary used by tests; `recs/base/app_command.py` has several callers. There is no compelling immediate cleanup here. More consequential duplication is the atomic writer above, not the small modules themselves.

30. **Tests emphasize successful lifecycle paths over fault boundaries.** The tree has dedicated tests for audio, config, daemon, edit, MIDI, OSC, recording, and runtime; it is not generally untested. Highest-value missing scenarios correspond to items 1-15: path traversal, concurrent output claims, >512 durable source events, partial multi-format open, disk-full journal close, project-switch rollback, post-timeout control execution, permanently blocked shutdown, malformed device-query JSON, extended card outage, OSC flood and DNS recovery. There are already substantial fake-heavy recorder suites ([test/runtime/recorder/test_sessions.py](../test/runtime/recorder/test_sessions.py), [test/runtime/recorder/test_control.py](../test/runtime/recorder/test_control.py)); add focused failure injections there rather than another parallel end-to-end harness. Existing broad integration/regression tests should remain distinct from hardware validation.
